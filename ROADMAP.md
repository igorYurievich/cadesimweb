## Исправления интерфейса симуляции (2026-11-05, по проверке Actividad 1.6)

- **Направление мотора:** движок считал реверс верно (после выдержки KT1 включается KM2, на U1/V1/W1 приходят L3, L2, L1), но в CSS `animation-direction: reverse` накладывался на зеркало `scaleX(-1)` и отменял его. Оставлено только зеркало: стрелка и вращение разворачиваются вместе.
- **Лампы:** в симуляции лампа без питания рисуется белой с тонким цветным ободком; цвет и свечение только когда горит. В редакторе лампа по-прежнему показывает свой цвет.
- **Таймер 9004:** под катушкой в симуляции показывается отсчёт «прошло / задано, с» (оранжевый при отсчёте, зелёный по завершении).
- **Стоп вместо паузы:** кнопка «■ Стоп» полностью останавливает симуляцию: время 0, память таймеров и защёлок, нажатые кнопки и результат расчёта сброшены, схема возвращается в редактор. «Шаг 0,1 с» остаётся и останавливает часы без сброса.
- Тест `Actividad 1.6: reverses the motor…` проверяет цепочку S2 → S3 → 10 с → KM2 → обратный порядок фаз. Локально запущены 7 тестов файла `actividades-1-6` (через временную заглушку vitest); полный `npm test` и `npm run build` не запускались. Интерфейс (лампы, отсчёт таймера, Стоп, зеркало ротора, символ -FC, перетаскивание) проверен в headless Chromium на сборке через esbuild.
- **Легенда потенциалов убрана** (плашка L1 L2 L3 N PE внизу поля): это были не кнопки, а только подсказка по цветам; провода по-прежнему красятся по потенциалу.
- **Тип 8005, конечный выключатель (-FC в Actividad 1.1.2):** раньше рисовался заглушкой с числом «8005» и давал `unknown-type`. Теперь известный тип: размыкающий контакт 11-12 с роликом, при нажатии размыкается (как кнопка, нажимается мышью). ## Находки по образцам для движка (разбор четырёх файлов Actividad 1.x, 2026-11-04)

Эти факты определяют разбивку и правила этапов 5.2–5.8.

- **Провод это отрезок, а не связь «клемма–клемма».** Электрическую связность нужно выводить из геометрии: совпадение концов, конец на теле другого отрезка (Т), точка 4001, клемма на конце или на теле отрезка. Именно поэтому граф клемм тяжёлый и разделён на три подэтапа.
- **Пересечения без точки есть и их много** (2, 14, 20, 19 по файлам 1.1.1, 1.3, 1.4, 1.5), и ни в одном нет точки 4001. Правило: пересечение без точки не соединяет.
- **Т-соединения** (конец отрезка на теле другого): 3, 11, 18, 12 по файлам. Без точки 4001 из них 0, 1, 2, 1. Правило: Т соединяет и без точки (раздел «Узел» в `reglas_editor.md`), но выдаётся предупреждение `t-without-junction`. Если автор знает, что в оригинале такое не соединяется, правило меняется одной константой.
- **Источников питания в образцах нет.** Фазы и нейтраль приходят с клеммной колодки `-X` (код 3007), у которой 5 клемм **без меток**. Правило по умолчанию: по порядку слева направо `L1 L2 L3 N PE`; если метки заданы, берутся метки. Требует подтверждения автора.
- **Тепловое реле связано по имени.** Силовая часть 6007 и контакт 8018 называются одинаково (`-FG1`); контакты 95-96 (NC) и 97-98 (NO) следуют за состоянием реле с этим именем.
- **Имена повторяются осознанно.** В 1.4 два контакта 7000 `-KM1` и два `-KM2`; в 1.5 катушка-таймер 9004 `-KM1`, контактор 2001 `-KM1`, полюс 2006 `-KM1` и контакт с выдержкой 7004 `-KM1` носят одно имя. Значит, источник по имени управляет и мгновенными, и таймерными исполнителями (см. «Решения, которые остаются за автором»).
- Провода кода 4000 используются и в силовой части, и в цепи управления, поэтому тип линии провода это подсказка, а не источник истины: потенциалы дают источники (5.4).
- Защитные аппараты 6001, 6004, 6006, 6012 и контактор 2006 (один полюс) в каталоге неоднозначны, но по клеммам ведут себя одинаково: полюса `1-2`, `3-4`, … проводят, пока аппарат не отключён.

### Контракт движка (итог этапа 5, проверен на реальных схемах в 5.8c)

- `simulate(input: EngineInput): EngineState`. Чистая функция: вход не меняется, результат зависит только от входа, состояние проходит через JSON.
- `EngineInput`: `schema`, `inputs` (`pressed`, `toggled`, `tripped`: всё по id элемента), `time` (симулированные секунды), `memory?` (защёлки, прошлые катушки, таймеры; возвращается в `EngineState.memory`), `options?` (`maxRelayIterations`, по умолчанию 50).
- `EngineState`: `nets` + `terminalNet` (5.2), `coils` по имени, `contacts` / `lamps` / `motors` / `tripped` по id, `faults` (`short-circuit`, `earth-leak`, `unstable`), `warnings`, `stable`, `iterations`, `memory`.
- Клемма адресуется `TerminalRef { element, index }`, ключ `"<id>:<index>"` (`terminalKey()`).
- Метки потенциалов: `L1 L2 L3 N PE` и заготовка `+ -` для DC.
- Изменение относительно каркаса: из `SimState` убрано поле `coils` (оно переехало в `EngineState.coils`); `SimState` теперь только `mode` и `time`.
- Реализованы сети, контакты, потенциалы и диагностика КЗ/утечки, катушки, моторы, тепловые защиты и таймер включения с задержанным контактом (этапы 5.2–5.7). Проверено на четырёх приложенных схемах 1.1.1, 1.3, 1.4 и 1.5.
- **Связность проводов (5.2a):** `buildWireLinks(wires) -> { groupOf: Map<id, группа>, groups: id[][], warnings }`. Точка 4001 тоже входит в группы. Группы нумеруются с 0 по наименьшему id провода в группе, поэтому порядок отрезков во входе ничего не меняет. Предупреждение `WireLinkWarning { code: 't-without-junction', at, wires: [конец, тело], message }` пока структурное; в `EngineState.warnings` (строки) оно переносится в 5.2c. Правило Т-соединения задаёт константа `T_JOIN_WITHOUT_JUNCTION` в `engine/wire-links.ts` (`true`: Т соединяет и без точки). Вспомогательные: `UnionFind`, `pointOnSegment`.
- **Помощники тестов (`tests/builders.ts`, `tests/scenario.ts`):** конструкторы мини-схем и `CadScenario` для импорта `.cad`, поиска элемента по имени, нажатия кнопок, имитации срабатывания защиты и продвижения симулируемого времени.
- Предупреждения движка (`EngineState.warnings`): `t-without-junction`, `mixed-line-kinds`, `unknown-type`. Парсер `.cad` предупреждает об обрезанных/повреждённых записях; уже прочитанная часть схемы остаётся пригодной для расчёта.

## Отложенный этап 6.7 — полное покрытие библиотеки символов CADe_SIMU 4.2

**Когда выполнять:** после завершения основных шагов 0–10. Этап не блокирует завершение редактора, симуляции и сохранения.

Расширить сопоставление и SVG-рендеринг с текущих 18 типов элементов до полного каталога: 267 схемных элементов + 42 реалистичных варианта (2D/3D), всего 309 команд. В `src/data/components.json` уже есть команды и названия. Задача 6.7 — не повторно собирать каталог, а сопоставить команды с графическими типами, клеммами и отрисовкой. Командный `id` из каталога не равен коду записи `.cad`; неизвестное соответствие нельзя угадывать по одному названию.

| Этап | Что делаем | Готово, когда |
|---|---|---|
| **6.7a** Сопоставление каталога | Для 267 схемных элементов назначить CAD-код/семейство, число и порядок клемм, геометрию и статус подтверждения; для 42 реалистичных вариантов зафиксировать базовый элемент и вид представления | Все 309 команд имеют явную запись метаданных; неизвестные соответствия отмечены как требующие образца, нет неявных догадок |
| **6.7b** Символы схемных элементов | Добавить параметризованные IEC SVG-примитивы и семейства для оставшихся функциональных элементов (источники, защиты, датчики, реле, двигатели, PLC/IO, логика, пневматика и др.) | Каждый подтверждённый из 267 функциональных элементов получает подходящий символ, поворот, терминалы и подписи; неизвестные показываются с явной пометкой, а не как будто они точно определены |
| **6.7c** Реалистичные варианты и покрытие | Поддержать 42 элемента групп `realistic-2d` / `realistic-3d` и переключение представления, если доступны исходные изображения; сверить весь каталог и наборы `.cad` | Покрыты все 309 команд; варианты 2D/3D связаны с функциональной моделью, визуально проверены примеры каждого семейства; пробелы во входных данных перечислены отдельно |

**Источники и ограничения:** `CADESIM/cadesimu_components.json` и извлечённые заметки дают полный список команд и имена. Четыре `.cad` в папке совпадают с уже подключёнными образцами. Папка не содержит исходного EXE, извлечённых bitmap-ресурсов или `.lib`, поэтому точные реалистичные 2D/3D-картинки и подтверждение неизвестных CAD-кодов потребуют соответствующих файлов/образцов. До их получения можно сделать функциональные векторные символы, но нельзя заявлять точное соответствие оригинальной графике.

## Решения, которые остаются за автором

- Подтвердить, включается ли пневматика в вторую очередь.
- Подтвердить стандарт обозначений IEC.
- Подтвердить правило источников: колодка `-X` без меток даёт `L1 L2 L3 N PE` по порядку слева направо (5.4a).
- Подтвердить правило Т-соединения: конец провода на теле другого провода соединяется и без точки 4001 (реализовано в 5.2a с предупреждением; на образце 1.1.1 таких случаев нет, на 1.3–1.5 их 1, 2, 1; сменить правило можно константой `T_JOIN_WITHOUT_JUNCTION`).
- В 1.5 катушка-таймер 9004 и контактор 2001 называются одинаково. Предложение: мгновенные исполнители (полюса 2001/2006, контакт 7000) следуют за катушкой сразу, контакт с выдержкой 7004 за состоянием таймера. Если в оригинале иначе, поведение схемы 1.5 в 5.8c определит, как должно быть (5.7b).
- Значение шкалы времени в параметрах таймера (`0` и `5`, `0` и `10`): предполагается шкала ×1 и секунды (5.7a), уточняется опытом в CADe_SIMU.
