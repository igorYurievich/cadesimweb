# Модель цепи и правила поведения элементов (предложение)

Это моя логика движка симуляции. Оригинал точных правил не публикует, поэтому всё, что не подтверждено, нужно проверить опытами в CADe_SIMU и поправить.

**Пометки:**

- **[оригинал]**: подтверждено данными из exe или открытых источников.
- **[предл.]**: моё предложение.
- **[тест N]**: решение зависит от опыта N из «Программы опытов» (раздел 12).

**Область:** режим «символ» (без 2D/3D, GRAFCET, ПЛК, связи с внешними устройствами). Ladder, логические элементы, пневматика, шаговые двигатели и частотники вынесены во вторую очередь (раздел 11).

---

## 1. Принципы модели

1. **Нет токов и напряжений в числах.** Движок отвечает только на вопросы «есть ли напряжение на клемме» и «между какими потенциалами включена нагрузка». Это то, что показывает оригинал (провода под напряжением ярче, элементы «активны/неактивны») **[оригинал]**.
2. **Электрическая часть решается графом.** Провода дают сети; замкнутые контакты дают проводящие рёбра; нагрузки (катушки, лампы, моторы) получают «питание», когда на их клеммах разные потенциалы одной системы.
3. **Логика релейная.** Катушка с именем X управляет всеми контактами с именем X **[оригинал]**. Состояния катушек и контактов пересчитываются до стабилизации.
4. **Время** идёт отдельно (таймеры, мигание, часы) в симулированных секундах; скорость симуляции регулируется ползунком **[оригинал: слайдер «Velocidad de simulación»]**.
5. **Защитные аппараты** отключаются при коротком замыкании и по ручной имитации перегрузки; расчёта тока нет.

## 2. Структуры данных

```ts
type PotentialId = { system: string; label: string };      // например { system:'AC1', label:'L1' }
type Net = { id: number; terminals: TerminalRef[] };        // электрически один узел
type Edge =
  | { kind: 'switch'; a: TerminalRef; b: TerminalRef; closed(): boolean }  // контакт, нож, плавкая вставка
  | { kind: 'diode'; anode: TerminalRef; cathode: TerminalRef }            // односторонний (DC)
  | { kind: 'resist'; a: TerminalRef; b: TerminalRef }                     // проводит, но помечает «пониженное»
  | { kind: 'load'; a: TerminalRef; b: TerminalRef; id: ElementId };       // катушка, лампа, обмотка
type ElementState = {
  id: ElementId; name: string;
  active?: boolean;        // катушка под напряжением / лампа горит
  tripped?: boolean;       // автомат, тепловое реле, предохранитель
  latched?: boolean;       // фиксируемые кнопки, бистабильные, телеруптор
  timer?: { phase: 'idle'|'counting'|'done'; t: number };
};
```

## 3. Потенциалы и системы

1. **Источник** кладёт на свою сеть потенциал `(system, label)`.
2. **Системы:**
   - `AC`: метки `L1`, `L2`, `L3`, `N` (метка `L` из «Alimentación Fase» считается синонимом `L1`) **[предл.]**;
   - `DC`: метки `+`, `-`.
3. **Преобразующие элементы создают новую систему**, когда их вход под напряжением (раздел 5): трансформатор, выпрямитель, источник питания, батарея (сразу DC).
4. **PE** (защитный провод) считается отдельной меткой: она не создаёт «нагрузочного» напряжения для катушек и ламп, но замыкание фазы на PE фиксируется как утечка (раздел 4.6).
5. **N и PE** считаются соединёнными между собой без ошибки **[предл.]**. [тест 9]

## 4. Основной алгоритм (один шаг вычисления)

### 4.1 Сети

Провода и совпавшие клеммы объединяются в сети (union-find). Сети перестраиваются только при редактировании, не при симуляции.

### 4.2 Проводящие рёбра

На каждом шаге строится список рёбер из текущих состояний:

- замкнутые контакты и полюса → ребро `switch`;
- неперегоревшие предохранители и неотключившиеся полюса автоматов → ребро `switch`;
- диод → одностороннее ребро;
- резистор, автотрансформатор (пусковой), реостат ротора → ребро `resist` (проводит; оттенок цвета «пониженное»).

**Нагрузки** (катушка, лампа, обмотка мотора) в проводящий путь **не входят**: потенциал через них не передаётся **[предл.]**. Это упрощение: цепочка «катушка последовательно с лампой» не работает. Нужно ли оно, покажет опыт 2.

### 4.3 Распространение потенциалов

Для каждого источника `P`: обход в ширину от его сети по проводящим рёбрам. Каждой сети присваивается множество достигших её потенциалов `P(net)`. Контакты проводят в обе стороны (так работают обходные цепи в релейной логике).

### 4.4 Питание нагрузок

Нагрузка между сетями A и B **под напряжением**, если есть `p ∈ P(A)` и `q ∈ P(B)` одной системы, `p ≠ q`, и пара допустимая:

- `(Lx, N)`, `(Lx, Ly)`, `(+, -)`;
- `(Lx, PE)`: лампа или катушка светится/срабатывает, но фиксируется утечка (4.6).

Если сети A и B достигаются одним и тем же потенциалом, или одна из них не получает потенциала, нагрузка **обесточена**.

### 4.5 Короткое замыкание

Короткое замыкание есть, если некоторая сеть получает **два разных потенциала** одной системы по проводящему пути (то есть без нагрузки между источниками).

Реакция **[предл.]** [тест 9]:

1. Найти защитные аппараты на путях, ведущих к этой сети. Отключается ближайший к месту замыкания (плавкая вставка перегорает, автомат/диффавтомат срабатывает).
2. Если защитного аппарата нет: симуляция приостанавливается, на листе подсвечивается место, всплывает сообщение «Короткое замыкание: L1–N».
3. Перегоревший предохранитель остаётся перегоревшим, пока пользователь не заменит его (меню в режиме симуляции «Заменить предохранитель»).

### 4.6 Утечка

Если потенциал фазы (L1/L2/L3/N по настройке) оказывается на сети, связанной с PE по проводящему пути, срабатывает **диффавтомат** на этом участке. Нет диффавтомата: предупреждение «Замыкание на землю».

### 4.7 Релейный цикл (стабилизация)

Состояния катушек определяются питанием, контакты следуют за катушками по имени. Они зависят друг от друга (самоподхват, блокировки), поэтому:

```
повторять до стабилизации (не более 50 раз):
    изменилось = false
    для каждого источника-по-имени X в порядке создания:
        новое = (хотя бы одна катушка X под напряжением)
        если новое != состояние(X): состояние(X) = новое; изменилось = true;
                                     перестроить рёбра и потенциалы
    если не изменилось: выход
если 50 итераций не хватило: «нестабильная схема» (колебания), состояние оставлено как есть, предупреждение
```

- **Последовательная обработка в порядке создания** даёт детерминированный результат в гонках (две катушки с взаимной блокировкой, подаваемые одновременно): побеждает созданная первой. Как в оригинале, выяснить опытом 4.
- **Время срабатывания контактора** по умолчанию 0. Режим «реалистичное время» (10–30 мс) **[предл.]** делает гонки видимыми, по умолчанию выключен.

### 4.8 Источник состояния по имени

- **Источник:** катушка контактора/реле, катушка таймера, бистабильная катушка, телеруптор, мотор-контактор, тепловое реле (его аварийное состояние), датчики **[оригинал: связь по имени]**.
- **Исполнитель:** контакт, вспомогательный контакт, силовые полюса контактора, контакты таймера, контакты теплового реле.
- Несколько катушек с одним именем: включена, если питается любая («ИЛИ») **[предл.]**. [тест 2]
- Исполнитель без источника остаётся в исходном положении.

### 7.2 Контакты таймеров

Таймер определён своей катушкой (раздел 8). Его контакты (по 4 типа на каждый вид) следуют за **состоянием выдержки**, а не за питанием:

| Вид **[оригинал]** | NA | NC |
|---|---|---|
| **Задержка на включение** | Замыкается через T после подачи питания; размыкается сразу при снятии | Размыкается через T после подачи питания; замыкается сразу при снятии |
| **Задержка на выключение** | Замыкается сразу при подаче питания; размыкается через T после снятия | Размыкается сразу при подаче питания; замыкается через T после снятия |

## 10. Двигатели

Общие правила:

- Направление определяется порядком фаз. Соответствие **L1→U1, L2→V1, L3→W1 = вращение вперёд**; любая перестановка двух фаз = обратное вращение **[предл.]**.
- Обороты — анимация с плавным разгоном (постоянная времени порядка 1,5 с) и торможением; численная модель не используется.
- Состояние мотора: «стоит», «разгоняется», «работает», «авария» (с текстом причины).

| Мотор | Правило **[предл.]** |
|---|---|
| **Motor trifásico** (U1 V1 W1) | Вращается, если на трёх клеммах три **разные фазы одной AC-системы**. Две фазы или одна: «обрыв фазы», не вращается. Одна фаза и нейтраль: не вращается |
| **Motor trifásico YD** (U1 V1 W1 U2 V2 W2) **[оригинал: символ есть]** | Определение схемы соединения по сетям: **звезда**, если сети `U2=V2=W2`, а на `U1,V1,W1` три разные фазы; **треугольник**, если сети `U1=W2`, `V1=U2`, `W1=V2`, а три узла получают три разные фазы. Иначе: «неверное соединение», обмотки не питаются. Звезда: анимация с пониженными оборотами и меткой «Y»; треугольник: полные обороты, метка «Δ» |
| **Motor monofásico** | Вращается, если две клеммы под L и N (или L и L). Реверс клеммами конденсатора, если они выведены (необязательно) |
| **Motor trifásico como monofásico** | Как однофазный с конденсатором (Штейнметц): работает от L и N на два вывода |
| **Motor Dahalander** (Dahlander) | Малая скорость: фазы на `1U 1V 1W`, `2U 2V 2W` свободны. Большая скорость: фазы на `2U 2V 2W`, `1U 1V 1W` соединены вместе. Обе группы питаются: «авария». Все параметры схем **[тест 8]** |
| **Motor dos velocidades** | Две независимые обмотки: питается группа 1 → скорость 1, группа 2 → скорость 2. Обе → «авария» |
| **Motor rotor bobinado** | Статор питается тремя фазами; для вращения роторные клеммы должны быть замкнуты (накоротко или через резисторы). Через резисторы: пониженные обороты (по числу включённых ступеней) |
| **Motor cc. imán permanente** | Вращается при `+`/`-`; смена полярности меняет направление |
| **Motor cc. independiente** (якорь + обмотка возбуждения) | Вращается, только если питаются и якорь, и возбуждение; при пропаже возбуждения: «потеря возбуждения», не вращается |
| **Freno** | Катушка под напряжением: тормоз отпущен; нет питания: тормоз затянут. Влияет на анимацию соединённого мотора по имени **[предл.]** |

**Двигатель и защита [тест 10]:** остановка мотора при отключении автомата или перегорании предохранителя происходит автоматически (нет напряжения на клеммах). Обрыв одной фазы работающего мотора: останавливается с предупреждением; тепловое реле может сработать, если параметр «чувствительность к обрыву фазы» включён.

## 13. Что сознательно не моделируется

- величины токов и напряжений, мощность, нагрев, времятоковые характеристики защит;
- сопротивление проводов и падение напряжения;
- частота сети и фазовые сдвиги, форма сигнала;
- пусковые токи, момент, нагрузка на валу;
- нагрузки как проводники (катушка последовательно с чем-то): см. 4.2.

Эти упрощения совпадают с задачами учебного симулятора; при необходимости модель расширяется (например, пассивные элементы как проводящие рёбра с резистором и решение методом узловых потенциалов).

## 14. Тесты движка (минимальный набор для старта)

1. Лампа параллельно и последовательно (два контакта).
2. Самоподхват кнопкой СТАРТ/СТОП.
3. Блокировка двух контакторов.
4. Таймер на включение (все шкалы), на выключение, ON-OFF.
5. Пуск звезда-треугольник по эталонной схеме из статьи (S2 → KM1+KM2+KA, через 4 с KM2 отпускает, KM3 включается).
6. Прямой пуск мотора + тепловое реле + красная лампа аварии.
7. Реверс мотора с двумя контакторами и взаимной блокировкой.
8. Короткое замыкание: отключение ближайшего защитного аппарата.
9. Обрыв фазы: мотор не вращается.
10. Датчик PNP/NPN и его нагрузка.
