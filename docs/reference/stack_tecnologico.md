# Какой стек использовать для улучшенной версии CADe_SIMU

## Итог

**TypeScript + Vite**, схема рисуется на **SVG**, движок симуляции вынесен в отдельный чистый модуль без привязки к интерфейсу. Интерфейс-панели на **Svelte или Preact** (или на чистом TS). Тесты на **Vitest**. Хранение: JSON + IndexedDB. Распространение: **PWA**, при необходимости оболочка **Tauri** для настоящего exe.

## Что и почему

| Часть | Выбор | Причина |
|---|---|---|
| Язык | TypeScript | Много типов элементов с разными параметрами (таймеры, моторы, датчики). Типы ловят ошибки до запуска, редактор подсказывает поля |
| Сборка | Vite | Быстрая, простая, поддерживает TS и тесты из коробки. Существующий HTML-проект переносится постепенно |
| Поле схемы | SVG (свой код на TS) | Готовое попадание мышью по элементу, подсветка проводов через CSS-классы (под напряжением / без), масштабирование без потери чёткости, экспорт в SVG/PDF и печать почти бесплатно. Canvas нужен только если схемы вырастут до десятков тысяч объектов |
| Панели интерфейса | Svelte или Preact | Свойства элемента, палитра, меню. Лёгкие. Можно обойтись и без фреймворка, с небольшим хранилищем состояния |
| Движок симуляции | Отдельный модуль на чистом TS | Принимает описание схемы, возвращает состояние клемм, катушек и контактов. Без DOM. Проверяется автотестами |
| Тесты | Vitest | Каждый опыт из плана проверки оригинала превращается в тест |
| Хранение | JSON с номером версии формата, автосохранение в IndexedDB, импорт/экспорт файла | Совместимость с `.cad` пока не нужна; облако и совместное редактирование на потом |
| Распространение | PWA | Работает офлайн, ставится на компьютер и планшет, ничего не нужно устанавливать |
| Настольное приложение (если понадобится) | Tauri | Оборачивает то же приложение в exe без переделки |

## Структура проекта

Три независимые части:

- `engine` — движок: граф клемм, обход от источников питания, пересчёт до стабилизации, таймеры. Никакого DOM.
- `model` — данные схемы: описание элементов, параметры, сохранение и загрузка.
- `ui` — редактор: поле схемы, палитра, панели свойств, меню.

Так движок можно развивать и проверять тестами, не трогая интерфейс.

## Что не брать

- **Electron**: тяжёлый без необходимости.
- **Unity / Godot**: избыточны для плоских схем.
- **C++ / Qt**: долго, непереносимо в браузер.

## Порядок работ

1. Каркас проекта (Vite + TS + Vitest) и три модуля.
2. Модель и движок для минимального набора: питание, кнопки, контакты, катушки, контакторы, реле времени, лампы, трёхфазный мотор.
3. Тесты по опытам из плана проверки оригинала (последовательное/параллельное включение, связь по имени, самоподхват, блокировки, таймеры).
4. Поле схемы на SVG: размещение, поворот, провода, узлы.
5. Панели свойств и палитра.
6. Остальные группы элементов, печать и экспорт.

## Решения, которые остаются за вами

- Оставить существующий HTML-проект основой или начать с нуля.
- Стандарт обозначений: IEC или ANSI.
- Входят ли в первую версию ladder, логические элементы и пневматика.
